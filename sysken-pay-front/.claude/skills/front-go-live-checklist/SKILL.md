# Front Go-Live Checklist

フロントを本番に出す前の棚卸し。目的は止めることではなく、**何が起きうるかをユーザーが理解した上で判断できる状態にする**こと。明らかに危険な状態を見つけたら、直るまで反映しない。

シス研Pay は部員の学籍番号・氏名とお金を扱う。フロントだけ見ても安全は保証できないので、**バックエンドの監査（`back-go-live-checklist`）を通しているかを最初に確認し**、まだなら合わせて実行するよう伝える。

## Step 1: 反映範囲を確認する

- 今回の変更は何か（`git log --oneline <ラズパイで動いているコミット>..HEAD -- .`）
- 画面の流れ・お金の表示（合計・残高・チャージ金額）・二重タップに関わる変更が含まれるか
- キオスク端末に誰が触れるか（部員なら誰でも / 部室の外の人も）

## Step 2: 棚卸し

**秘密情報**
- `.env` が Git 管理に入っていないか（`git ls-files | grep -i '\.env'`。`.env.sample` は可）。過去の履歴も確認（`git log --all --diff-filter=A --name-only -- '*.env*'`）
- **`VITE_` で始まる環境変数はすべてビルド後の JS に埋め込まれ、誰でも読める**。パスワード・トークンなどが `VITE_` 変数や `src/` に入っていないか確認する（管理者パスワードはバックエンドの `ADMIN_PASSWORD` で確認する作りになっている）
- 管理者パスワードがホーム画面に戻ったときに破棄されるか（`pages/index.tsx` の `clearAdminPassword()`）
- `git grep -n -i -E 'password|secret|token' -- src` でハードコードがないか

**お金の表示と操作**
- 購入・チャージの確定ボタンを連打したとき、リクエストが二重に飛ばないか（送信中はボタンを無効化しているか）を、該当ページと hooks（`useCart`、`useCharge`）を読んで確認する
- 金額の表示（`¥` とカンマ区切り）、残高不足のときの表示が正しいか
- エラー時（API に届かない・4xx/5xx）に、成功したように見える画面へ進まないか

**キオスク表示**
- `front-pi-display-ui` の手順で、変更した画面が 800x480 に収まることをスクショで確認したか
- `pnpm build` が通り、`pnpm preview:pi` で表示できるか
- ラズパイの再起動後に、フロントのサーバーとキオスクのブラウザが自動で立ち上がるか（未設定ならそう報告する）
- 開発者ツールやアドレスバーが出ない設定（`--kiosk`）になっているか

**依存とテスト**
- `pnpm audit --prod`
- `pnpm exec vitest run src/test`、`pnpm lint`、`pnpm build`
- `src/types/api-schema.d.ts` がバックエンドの `docs/openapi.yaml` と一致しているか（`pnpm generate:api` 後に差分が出ないか）

**戻す手段**
- 壊れたときにラズパイで前のコミットに戻す手順（`front-safe-rollback` の 4-D）をユーザーが把握しているか

## Step 3: `/security-review` を実行する

反映するブランチの変更をビルトインの `/security-review` でレビューする。XSS（商品名・ユーザー名の表示）、秘密情報の露出を重点的に見てもらう。

## Step 4: 結果を報告し、判断を仰ぐ

「問題なし / 直してから反映すべき / 反映後でよいが対応推奨」に分けて、技術用語に一言説明を添えて報告する。

- 「直してから反映すべき」が残っている間は反映しない
- 「絶対に安全」とは言わない。フロントの監査では見ていないもの（API の認証、DB、ラズパイ自体の守り）を一言添える
- ユーザーが残リスクを理解して「反映する」と決めたら、そこで初めてデプロイ作業に進む
